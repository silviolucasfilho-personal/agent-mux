# Shared Trace MCP and Harness Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the same bounded, read-only trace investigation tools to Claude, Codex, AGY, the CLI and TUI.

**Architecture:** Wrap milestone 1's exact query core in a scoped service. Serve eight tools over stdio, publish bounded live snapshots from the mux, and configure the shared service through generated native artifacts.

**Tech Stack:** Rust, rusqlite, Tokio, serde, a maintained Rust MCP SDK, JSON Schema generation/validation and authenticated opaque cursors; pin compatible dependency versions during Task 1.

**Spec:** [Heimdall and generic agent service design](../specs/2026-09-14-heimdall-agent-service-design.md)

## Global Constraints

- Every agent is defined completely by an `AGENTS.md` source and has generated artifacts for each harness.
- No agent may require an agent-specific Rust file, implementation branch, embedded persona, or compiled registration.
- Adding, changing, or removing an agent must require only Markdown/configuration changes and artifact regeneration, never rebuilding agent-mux.
- Do not overwrite a user's repository-root `AGENTS.md` to activate an agent.
- All v1 tools are read-only and carry corresponding MCP annotations.
- List limit defaults to 20 and is capped at 100.
- Default query deadline: 2 seconds; analytics/comparison: 5 seconds.
- Maximum concurrent requests: 4; bounded waiting queue: 16.
- Maximum serialized response: 64 KiB. Cursors expire after ten minutes.
- Publish live snapshots every second; after five seconds without a heartbeat treat live state as stale, not exited.
- Automatic model investigation is disabled by default.
- Do not add operational write tools, remote transport, hard-coded agent workflows, or another trace ingestion pipeline.
- Preserve unrelated work. At execution, inspect current instructions/status and use an isolated checkout when appropriate. Do not execute this plan merely because it has been written.
- Native flags, installation paths and supported versions must be verified against installed binaries and official documentation before implementing an adapter. Never guess capability support.
- Tests run against temporary databases/configuration roots. Live harness tests are opt-in and must report unavailable harnesses as unverified.

### Proposed service types (Task 1 defines these)

`Scope` contains one normalized workspace or explicit all-workspaces authorization. `ServiceConfig` contains resolved DB path, scope, runtime snapshot directory and limits. `Request` is an enum with the eight tool argument structs named below. `Envelope` has the exact version-1 envelope fields in the spec and tool-specific data serialized through typed structs, not unchecked arbitrary JSON. `ServiceError` carries code, message and retryability. `TraceService` owns configuration and opens per-request read-only connections.

Argument structs: `BriefingArgs`, `ListSessionsArgs`, `GetSessionArgs`, `TimelineArgs`, `SearchArgs`, `AnalyzeSkillsArgs`, `CompareRunsArgs`, `HealthArgs`. Their fields and defaults are exactly spec section 8; unknown fields are rejected. Use `#[serde(deny_unknown_fields)]`. `Request::Health` has no arguments; the other variants contain the corresponding argument type.

- [ ] **Step 3 — Implement the smallest complete deliverable.**

Authenticate cursor payloads with a per-service random key; reject modified filters/scope and expired tokens. Restart invalidates earlier cursors with a refresh diagnostic. Use timestamp plus immutable ID ordering and bind upper bounds. Do not hold SQLite transactions between requests; warn that late updates can change data.

```text
request -> validate -> admit (4 running / 16 queued) -> open read-only DB
        -> install deadline/cancel progress hook -> query -> bound result -> serialize
        -> remove progress hook and release connection/admission slot
```

Use rusqlite interrupt/progress support and a blocking executor; a timed-out future alone is insufficient. Apply 2s or 5s total deadlines including lock waits. Return BUSY above admission limits. First truncate excerpts, then paginate rows, always valid JSON. Size-budget the complete wire result including duplicated text/structured content, not only data. A single oversized detail retains fields with truncation metadata.

Test queue saturation with a barrier instead of flaky sleeps, cancellation of a recursive query, locked DB deadline, expired/tampered cursors, unknown fields, invalid windows, 4KiB search ceiling and >64KiB source content.
