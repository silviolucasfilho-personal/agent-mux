# Portable Agents, MCP and Monitoring Delivery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved architectural direction through three reviewable milestones.

**Architecture:** AGENTS.md is the sole source of every agent's behavior; generic Rust services generate native artifacts, expose trace facts, and optionally schedule investigations. No agent-specific Rust remains.

**Tech Stack:** Existing Rust agent-mux repository; dependencies and native adapter compatibility are validated within the milestone plans.

**Spec:** [Heimdall and generic agent service design](../specs/2026-09-14-heimdall-agent-service-design.md)

## Global Constraints

- Every agent is defined completely by an `AGENTS.md` source and has generated artifacts for each harness.
- No agent may require an agent-specific Rust file, implementation branch, embedded persona, or compiled registration.
- Adding, changing, or removing an agent must require only Markdown/configuration changes and artifact regeneration, never rebuilding agent-mux.
- Do not overwrite a user's repository-root `AGENTS.md` to activate an agent.
- All v1 tools are read-only and carry corresponding MCP annotations.
- List limit defaults to 20 and is capped at 100.
- Default query deadline: 2 seconds; analytics/comparison: 5 seconds.
- Maximum concurrent requests: 4; bounded waiting queue: 16.
- Maximum serialized response: 64 KiB. Cursors expire after ten minutes.
- Publish live snapshots every second; after five seconds without a heartbeat treat live state as stale, not exited.
- Automatic model investigation is disabled by default.
- Do not add operational write tools, remote transport, hard-coded agent workflows, or another trace ingestion pipeline.
- Preserve unrelated work. At execution, inspect current instructions/status and use an isolated checkout when appropriate. Do not execute this plan merely because it has been written.
- Native flags, installation paths and supported versions must be verified against installed binaries and official documentation before implementing an adapter. Never guess capability support.
- Tests run against temporary databases/configuration roots. Live harness tests are opt-in and must report unavailable harnesses as unverified.

## Plans and order

1. [Markdown agents and correct analytics](2026-09-14-markdown-agents.md): 8 tasks. Complete data-only package discovery, native artifacts, one launcher, exact evidence and removal of agent-specific Rust.
2. [Shared MCP and harness integration](2026-09-14-agent-mcp.md): 6 tasks. Add scope, limits, live snapshots, eight tools and native connection verification. This completes the first release.
3. [Optional monitoring and review memory](2026-09-14-agent-monitoring.md): 6 tasks. Add durable changes/review state, declarative triggers and bounded managed investigations.

Each plan has its own file map, proposed interfaces, regression examples, commands, commits and exit gate. Run them in order; milestone 3 is independently scheduled after the interactive release.

## Planning decisions

- Agent-specific behavior and prompts are normal disk assets. `agents/heimdall/AGENTS.md` is the bundled example, never a Rust include or registry entry.
- Native artifact formats are generated by provider adapters. Staging files are not assumed native discovery paths; compatibility evidence is required before each installer mapping is implemented.
- Exact native identifiers are required to bind live and stored sessions. Cwd similarity yields candidates only.
- Read-only MCP serves generic `agent_mux_*` tools; no raw SQL or action tool is introduced.
- Managed execution is optional and cannot be enabled for an adapter whose selected limits cannot be enforced.
- Milestone 3 introduces a committed change sequence because timestamps alone miss late observations and corrections.
